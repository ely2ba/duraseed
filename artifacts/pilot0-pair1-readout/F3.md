## Field definitions and detailed records

- Counts and rates above reproduce each profile's `panels.targeted` and `panels.sentinel`. Syntactically invalid counts are the recorded invalid rates multiplied by 4,096; valid counts are their complements. Strategy multiplicities are frequency histograms of the source `verified_strategy_family_counts` values.
- Exact-success rate is successes divided by draws. The equal-item posterior mean averages `(successes + 0.5) / (trials + 1)` over items. Posterior soft-cover averages each item's Jeffreys posterior probability that success probability is at least `tau`; it is not a count of items whose point estimate crosses the threshold. See [analysis.py](../../src/duraseed/evaluation/analysis.py).
- Pass@k is the mean, across items, of the unbiased estimator `1 - choose(n-c,k) / choose(n,k)`. Only `k = 1, 4, 16` are reported because each item has 16 already-required draws; no additional draws are used.
- Syntactic invalidity is `not exact_verification.valid_syntax`, not `not valid_answer_tag`. It includes answer extraction, lexing, and parsing failures. A syntactically valid answer may still fail operand, operation, or target verification. See [TCES verifier](../../src/duraseed/tasks/tces/verifier.py).
- In this profile reducer, a length stop is identified by `sampled_tokens >= sampling_max_tokens`. Detected loops are counted only among those completions: the detector tests the final 1,024 token IDs at lags 4 through 256 and returns true if any lag has at least 0.80 token agreement. The loop fraction denominator is length-stopped completions, not all completions. See [profile reducer](../../src/duraseed/pilot0_profiles.py) and [loop detector](../../src/duraseed/runners/capability_dose_evidence.py).
- Unique completions count distinct exact completion-text strings within the panel. Mean sampled-token surprisal is the negative mean of recorded token log probabilities, pooled over sampled tokens; logprob coverage is reported separately. This is not a full-vocabulary entropy estimate.
- Verified strategy-family counts include only reward-1 completions and use the verifier's `strategy_family_id`. They are separate from the manifest's assigned-family counts. All exact identifier/count pairs are in each profile's `panels.<role>.verified_strategy_family_counts`; per-assigned-family and per-item records are in `families` and `items` in the [unchanged full profiles](../../runs/pilot0/pilot0-pair1-seed11-20260825T125100Z/seed-11/pre-b-profiles.json). B-S is array element 0; B-G is array element 1.
